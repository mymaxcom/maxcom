MAXCOM, theme author guide, contract {{contract}}

How to make a theme for the surau TV display

This guide is for people who know CSS but not MAXCOM. Every table in it is generated straight from the MAXCOM code, so what is written here is what the MAXCOM box really does. The example in this guide is a real theme that the box validator has already checked.

1. What a theme is

A theme is one file named theme-name.maxtheme. It changes how the surau TV display looks: colours, layout and background pictures. It does not change what is shown. Prayer times, the clock, the countdowns, the next-prayer chip and the surau logo are on every screen at all times, because the congregation relies on them.

There are two ways to change the look. The first is the Ubah suai menu in the app, which is safe and needs no CSS. The second is a theme file, which gives full freedom to anyone who can write CSS. This guide is about the second way.

Every theme is installed on top of one built-in theme, called its base. Anything your theme does not style falls back to that base, so you only write the differences.

The value of a style is decided by layers, from the lowest to the highest:

  1. MAXCOM base styles, including the protected rules (section 10).
  2. The built-in theme named as base.
  3. Your theme files: theme.css, then screens/<id>.css, then arabic.css.
  4. The defaults in theme.json.
  5. The surau's choice in the Ubah suai menu for all screens of the theme.
  6. The surau's choice in the Ubah suai menu for one screen only.

The surau's choices are written straight onto the stage as style variables, so they always override your theme files. That is intended: a surau has the right to change the colour or text size of a theme it installed.

2. Start by downloading

The easiest start is to download a theme that already exists. In the app: Tetapan, Templat paparan, pick a theme, then Muat turun tema. A built-in theme downloads as a starting pack. The checkbox Sertakan ubah suai saya (on by default) bakes the surau's own choices into defaults, so the file reproduces what the surau sees now.

Open the file as a zip, edit theme.css, change name and title in theme.json, zip it again and upload it through Tetapan, Templat paparan, Muat naik tema. The box checks the file and shows a preview. Press Pasang, then Guna sekarang.

3. Inside a .maxtheme file

A .maxtheme file is an ordinary zip. The file name is the theme name in lowercase letters, digits and hyphens, at most 32 characters, followed by .maxtheme, for example hijau-siti.maxtheme. Only the fixed paths below are allowed. Any other file, nested folders, a zip inside a zip and symbolic links are refused.

A theme file holds no fonts in this version of MAXCOM: a folder fonts/ and any @font-face are refused. The font is the surau's choice in the Ubah suai menu, from the fonts MAXCOM already carries. A picture is referred to as url(../images/kuliah.png) or url(images/kuliah.png). Any other address is refused. Pictures are PNG or JPEG only (WebP is refused). The box does not keep the bytes you send: it reads each picture and draws it again as a plain PNG or JPEG of the same size, and only that copy is ever shown on a display.

Every rule in your CSS is placed under your own theme's stage when the theme is installed (.stage[data-theme='your-name']), whether it is in theme.css, arabic.css or screens/<id>.css. A rule can only reach the elements inside your stage, never another theme, the page around it or the MAXCOM screens for setup, pairing, recovery, stopped box and network check, which never load your theme at all. Because of this, html, body, #root and :root cannot be styled; a :root rule that sets only --variables is allowed and applies to your stage. An attribute selector on class is allowed only as [class~='name'] with one plain class name. A rule that reaches the elements next to the stage (.stage + x, .stage ~ x) is refused.

In this version a theme is a re-skin of one of the built-in themes, not a new layout. The box reads your CSS with an allow-list: what is not listed is refused. Selectors may only be classes (for example .region-clock), the data attributes of the contract (data-screen, data-kind, data-phase, data-card, data-live, data-live-layout, data-harakat, data-align, data-lang, data-dim, data-pic, data-role, data-theme, data-template), and :first-child, :last-child, :nth-child() and :not(). Type selectors, *, #id, pseudo-elements (::before, ::after, ::marker, ::selection), :has(), :is(), and every class of the box's own overlays (.host-exit, .netcheck, .preview-ribbon) are refused.

The properties you may use are: color, background-color, background and background-image (your own pictures and gradients only), background-size, background-position, background-repeat, border (width up to 0.5rem), border-radius, outline (up to 0.3rem), box-shadow and text-shadow (blur up to 2rem, spread up to 0.5rem, offsets up to 1rem), padding, margin, gap, font-weight, font-style, text-transform, letter-spacing (0 to 0.3em), word-spacing, line-height (1 or more), text-align, size properties (width, height, min-*, max-*, never on the clock, the prayer times, the next-prayer chip or the logo), and variables: your own --pack-name variables (colours, gradients, your pictures, numbers and small lengths) and the base colours --accent, --accent-2, --text, --ink, --muted, --paper, --hair, --rule, --mint, --green, --sunset, --harakat, --accent-rgb and --glass-rgb (colours only). Every other theme variable is refused, because the built-in themes use them for fonts, sizes and angles. A property with a bound does not accept var() or calc(): write the number. Everything else is refused, including transform, scale, rotate, zoom, opacity, visibility, display, position, top and the other offsets, z-index, overflow, clip, mask, filter, mix-blend-mode, font-family, font-size (the menu's text size controls do that), direction, text-indent, text-decoration, list-style, content, animation, transition, cursor and pointer-events, with or without a vendor prefix. !important, a string inside a custom property (--name) and a var() inside image-set() are refused too. Any at-rule other than @media, @supports, @layer, @container and @charset is refused.

4. theme.json

theme.json is the identity card of the theme. The field name is the file name and the identifier of the theme. It cannot change later, because the same theme is recognised by that name. The field title is the name the surau sees in the gallery, shown exactly as you write it. The field version is a whole number that you raise each time you upload a new version. The field contract is the contract number your theme was made for. The field base is the built-in theme that it extends.

The field defaults holds the menu choices that the theme ships with, in the same shape as the surau's own choices: semua for all screens and skrin for single screens by id. The known keys are listed in the table in section 7. An unknown key is refused, and the message names it. A background picture cannot be in defaults; put the picture in images/.

The stage also carries data-template, data-theme, data-pack and data-bg. They exist, but they are not part of the contract promise, so do not depend on them in a theme that should last.

Each screen has one fixed id that will never be renamed. Select a screen with .stage[data-screen='poster'], or put that screen's CSS in screens/poster.css. In a screens/<id>.css file every selector is scoped to that screen automatically, so you do not write [data-screen] yourself. The background picture of one screen goes in images/<id>.jpg or .png. A picture images/semua.* is used on every screen that has no picture of its own.

The background picture that shows is chosen in this order, highest first: the surau's picture for that screen, the surau's picture for all screens, the picture in your theme, the surau's background list, and last the MAXCOM default pictures.

6. Regions

Every screen is divided into regions with fixed class names. Use them to restyle parts of a screen (colours, borders, spacing). Not every region exists on every screen, so write CSS that does not break when a region is missing.

The attribute data-align on the stage (left, center or right, following the surau's choice) sets the text alignment inside .region-main. If your theme rearranges that region, read the same attribute in your CSS.

Content screens. The screens whose data-kind is content (the poster, the lecture, the programme, the hadith, the zikir, the announcements, the calendar, the donation box, the verse and the three Arabic-led screens arab-ayat, arab-hadis and arab-zikir) fill the whole stage with a shell, .screen--shell: the surau name and logo in .region-brand, the compact clock and the next-prayer chip together in .shell-top, the card in .region-main and the compact prayer strip in .region-prayers. The main layout of the prayer screen is .screen--main; the two never share a rule of the built-in themes, so write for the one you mean. The compact clock, the next-prayer chip and the compact strip are protected like their large forms (section 10). In data-live-layout the stage says how the live screen is drawn, and data-harakat is present when the surau's mark colour is on for Arabic text (section 8).

7. Style variables

Every control in the Ubah suai menu writes one CSS variable or one attribute on the stage. Your theme CSS reads the same variables, so a menu choice and a theme file never fight. If you set --accent in your CSS, the surau can still change it in the menu, and the surau's value wins.

Values in defaults are written with the same Malay words as the menu (for example "align": "tengah"), while the attributes on the stage carry English words (data-align="center"). The table above shows both.

8. Arabic text

Arabic text on the verse, hadith and zikir cards carries the class .arab, and its translation carries .arab-tarjamah. Write your Arabic typography in arabic.css (optional) or in theme.css. Right to left is used only inside Arabic text blocks; the layout of the stage stays left to right.

When you upload a file the box checks everything and collects all the problems into one report, not only the first. There are two kinds. An error blocks the install. A warning does not; it tells you that a style will not show on the T95 box (section 11).

10. Protected elements

Prayer times, the clock, the countdowns, the next-prayer chip and the surau logo cannot be lost. No theme can hide them, and the rules below are added last so that they win.

11. Chrome 91 limits

The T95 box runs the Chrome 91 browser. Newer CSS does not work there, and the box will not show those styles. The validator gives a warning (not an error) when it finds any of the following. Prayer times and the clock are not affected, but your theme will look different from what you see on a computer.

The safe way: test your theme on a real T95 box, or in a browser of the same version, before sharing it.

12. Uploading and versions

A theme is uploaded by a Pentadbir Surau, with the same permission as the other screen settings. The box checks the file, keeps it aside and shows a preview before you press Pasang. An uploaded theme is not used until the surau chooses it with Guna sekarang.

A box accepts at most 10 theme installs in an hour. The same name with a higher version number updates the installed theme. The same or a lower version is refused with a clear message. A different name installs a new theme. Up to 30 uploaded themes can be installed. The surau's own menu choices stay after an update. Values for screens or variables that the new version no longer uses are kept but ignored, so a later version can use them again.

An installed theme is stored on the box and copied to the cloud within the surau's storage limit, so a replacement box and editing away from the surau do not lose it. Only a theme that is not in use can be deleted, and built-in themes cannot be deleted.

The app offers an uploaded theme only when every box of the surau reports a contract equal to or higher than the contract of that theme. A box older than your contract would not accept it, so the theme does not appear until that box is updated.

An installed theme is stored once: when a theme is updated or deleted, the file of the old version is removed from the box. The address of a theme's files contains a short code taken from the file itself, so a new version always has a new address.

After a theme loads, the display checks the protected elements on every screen by itself, again every minute, and again after any animation or transition ends. If something is lost, the display goes back to the base theme, the theme card in the app shows Tema tidak sah, and Semak MAXCOM reports it. The viewers are never left without prayer times.

13. The contract promise

Everything listed in this guide (screen ids, attributes, region classes, Arabic classes, style variables, file paths and limits) is contract {{contract}}.

The contract number goes up only on a breaking change. Older themes keep working on their contract version for at least a year.

New things that break nothing are added without raising the contract number. If you write "contract": 2 while the box supports only contract {{contract}}, the box says that this theme needs a newer MAXCOM.

14. Sharing a theme

A .maxtheme file is small and can be sent through a phone messaging app or e-mail like any file. The receiver uploads it in their MAXCOM app with the steps in section 2.

Choose a name that other people are unlikely to use, so that your theme is not mistaken for an update of another theme with the same name. Raise version each time you hand out a new version. A theme file carries no secrets and no surau data; it is only a look.

The pictures in the file are the responsibility of the theme author. Make sure you have the right to use them and to let others use them, and do not include a picture that you may not distribute.

This guide exists as a web page and as a PDF, in Malay and in English. The PDF can be sent through a messaging app like any other file.
